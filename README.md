# ngIRCd Homepage

This is the *homepage* of ngIRCd, a free, portable and lightweight Internet
Relay Chat (IRC) server for small or private networks.

The homepage itself can be found on <https://ngircd.barton.de>.

This source code is available on
[GitHub](https://github.com/ngircd/ngircd-web).

## Building

The site is generated by [Zola](https://www.getzola.org/):

```bash
zola serve    # Local preview on http://127.0.0.1:1111
zola build    # Generate the site in public/
```

Content lives in `content/` (Markdown), the layout in `templates/`, and
everything in `static/` is copied as-is. The current release and the download
servers are configured in `config.toml`.

The site must stay fully usable in text-mode browsers like lynx and w3m: no
JavaScript, no content that is only visible with CSS. Check with e.g.
`lynx -dump public/index.html`.

Old URLs of the former PHP site are redirected by `static/.htaccess` (Apache).

## Conventions

- Build with `zola build` without any warnings, using the Zola version of the
  GitHub workflow (`.github/workflows/`). Never commit `public/`.
- Internal links and assets must be relative (e.g. `../download/`, or `rel` in
  `templates/base.html`), so that the site works on all mirrors and in
  subdirectories. Don't use `@/` links in the content, Zola renders them as
  absolute URLs. Only the canonical link, `og:url`, `og:image` and the
  sitemap use the main site on purpose.
- Shortcodes are Tera components in `templates/components.html` (e.g.
  `{{ <release /> }}`, `{{ <years /> }}`), used in the Markdown content.
- Never write the release number, its date, or the number of years literally
  into the text: use `config.extra` (`release`, `release_date`,
  `first_year`) or the components.
- Link files of the ngIRCd sources via `{{ src }}` (set at the top of each
  content file), i.e. on the tag of the current release, not on `master`.
  Make sure every linked file exists at that tag.

## Updating the Manual Pages

The HTML manual pages in `static/man/` are generated from the manual page
templates of an ngIRCd release tag using `pandoc`:

```bash
./update-manpages.sh [<ngircd-repository> [<release> [<revision>]]]
```

The defaults are the ngIRCd sources in `../ngIRCd`, the release set in
`config.toml`, and its tag `rel-<release>`. Pass another Git revision to
generate the pages of a release that is not tagged yet, and regenerate them
from the tag once it exists.

Commit the updated HTML files afterwards.

## Releasing a New ngIRCd Version

1. `config.toml`: update `release` and `release_date`.
2. `content/news.md`: add the release on top of "Recent releases" (keep five
   entries), and review the warning box.
3. Regenerate the manual pages with `update-manpages.sh` (see above).
4. `content/_index.md`: update the `ngircd --help` output.
5. Check that all `{{ src }}` links exist at the new tag.

## Publishing

Pushes to `master` are published to <https://ngircd.github.io> automatically
by the GitHub workflow. The main site <https://ngircd.barton.de> is updated by
hand on its web server:

```bash
zola build -o "${TMPDIR:-/tmp}"/ngircd-web --force
rsync -rlc --delete -i "${TMPDIR:-/tmp}"/ngircd-web/ /srv/web/ngircd.barton.de/
```

Don't build into the DocumentRoot directly: `zola build --force` removes the
output directory first. Zola rewrites all files on every build, so `rsync -c`
compares their contents: only changed files are copied, unchanged ones keep
their modification time.
